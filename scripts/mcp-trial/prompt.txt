あなたは技術ブログの編集者で、CMS を MCP のツールだけで操作します。cms（編集者の鍵）と cms-reader（読み取り専用の鍵）の 2 つの MCP サーバがあります。以下のシチュエーションを順に実際にやってください。できない物は「何が無くて困ったか、何があれば良かったか」を書き、無理に回避せず次へ進んでください。ツールの description は仕様として読んでください。

最後に日本語で報告を書き、カレントディレクトリの report.md に保存してください。報告の形式: シチュエーションごとに「できた / できなかった / 迷った」と 1〜3 行の理由。最後に「足りない API（無くて困った物）」「description や応答の分かりづらさ」「バグと思う物」の 3 つの一覧を、優先度の高い順に。

準備: list_types で型を確かめる（authors と posts。posts は title / slug / summary(200 文字まで) / body / tags(複数選択) / publishedOn(日付) / featured / author(authors への参照) を持つ）。

1. 公開してすぐ取り消し: 記事を 1 件作って公開し、直後に取り消し、もう一度公開する。
2. 参照のある記事: 著者を 1 人作り（未公開のまま）、その著者を参照する記事を作る。publish_check で何が出るか見て、著者ごと公開する。その後、著者を取り消そうとして何が起きるか見る。
3. 10 件作って探す: タグ・公開日・featured を変えた記事を 10 件作り、一部だけ公開する。search_entries で「FLIX タグの物」「公開中の物」「2 ページ目」を取ろうとする。
4. 直して戻す: 公開済みの記事の本文を直し（CHANGED）、diff で差を見て、再公開する。さらに直した後で「やっぱり前に公開した中身に戻したい」を試みる。
5. 競合: 同じ記事を 2 回 get_entry し、1 回目の version で保存し、続けて 1 回目の version のまま保存する（CONFLICT）。エラーから正しい復旧をする。
6. 読み取り専用の鍵: cms-reader で記事の作成・公開を試みる。下書きの読み取りは試みる。
7. 消したい: 間違えて作った記事を消そうとする。
8. 画像と動画: 本文に画像を入れたい。何ができて何ができないか。
9. 下書きを人に見せる: preview_url を取る。
10. 予約公開: 来週の月曜 9 時に公開したい。
11. 巨大な本文: 300 KB くらいの本文を入れ、get_entry で読み戻す。
12. 値の形: tags / publishedOn / featured / author に、型を見て正しい形の値を入れる。間違った形（tags に文字列、publishedOn に "来週"）も試して、エラーの分かりやすさを見る。
13. 要約の上限: summary に 250 文字入れて公開しようとする。
