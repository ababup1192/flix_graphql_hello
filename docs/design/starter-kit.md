# 公開側の配り方（2026-09-12 の決め）

## 方針

**エディタとサーバに集中する。**公開側の画面は作らず、**見本を配る**。

理由:
- テンプレートを出すと「色を変えたい」「メニューを足したい」「独自ドメイン」と際限がなく、
  WordPress と Ghost の土俵になる。あちらは 10 年かけて作り込んでいる
- class 無しの HTML と Markdown の往復は「自分で作る人」に効く特徴で、
  テンプレートを出すとそこが使われなくなる
- ホスティングはしない。Vercel や Cloudflare Pages に置くのは使い手の仕事

## 配る物

`npx` 一発で自分の環境に取れる形（shadcn と同じ「コピーして使う」考え方）。
依存として配らない。更新で見た目が変わる心配も、上書きの優先順位で戦う必要もない。

### 1. フレームワークに依存しない 3 つ（これを先に作る）

| 物 | 中身 |
|---|---|
| `article.css` | class 無しの HTML に当てる CSS。**テーマ 3 つ**（note 風 / 技術記事風 / 企業サイト風）。変数（色と幅）を上に出す |
| 型付きのクライアント | コンテンツ API の GraphQL から生成。どのフレームワークでも使える |
| Markdown の方言のプラグイン | unified 系。`{key=value}`、画像の次の行の `*…*`、`> — [出典](URL)`、`title="foo.js"` を解釈。`asset:ID` と `entry:ID` の解決も |

この 3 つがあれば、フレームワークごとの作例は「繋ぐ 100 行」で済む。

### 2. フレームワークの作例（3 つだけ）

| # | 物 | 理由 |
|---|---|---|
| 1 | **Next.js** | ヘッドレス CMS の作例で最も選ばれる。`~/Desktop/flix-cms-example` に既にある |
| 2 | **Astro** | コンテンツ主体のサイトで伸びている。class 無しの HTML と相性が良い |
| 3 | **Nuxt** | Vue 側の代表。要望が出てから |

**8 つ並べない。** 作る労力より**動かし続ける労力**が問題になる。
フレームワークは年に何度も版が上がり、CMS 側を変えるたびに全部を直すことになる。
Svelte / Elm / Ember / Angular はこの用途での採用が少ない。

## やる順

1. `article.css` を 3 テーマに（今の作例の CSS が土台）
2. 型付きのクライアント
3. Markdown の方言のプラグイン
4. Next.js の作例をその 3 つで書き直す
5. Astro を足す
6. Nuxt は要望が出てから

## 狙う使い道

| | microCMS の代わり | 社内ドキュメント | ブログ |
|---|---|---|---|
| 書き味 | 要る | 要る | 要る |
| API | 要る | 要らない | 要らない |
| 公開サイト | 自分で作る | **見本を使う** | **見本を使う** |
| 検索 | API 経由 | 要る | あると良い |
| 権限 | 要る | 要る（細かく） | 要らない |

3 つとも同じ CMS で足りる。違うのは「公開する場所を誰が用意するか」だけ。
見本を配れば、社内ドキュメントとブログの使い手もコピーして始められる。

**社内ドキュメントで足りない物**（richText の後に検討）:
- 全文検索（今は一覧の絞り込みだけ）
- 細かい権限（今は組織とプロジェクト単位）
- 文書どうしの逆引き（内部リンクは記録しているので作れる）
