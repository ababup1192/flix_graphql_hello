# CMS MCP 試用レポート(2026-09-08)

編集者の鍵 `cms` と読み取り専用の鍵 `cms-reader` の 2 つの MCP サーバだけで、13 のシチュエーションを実際に操作した結果。

準備: `list_types` で `authors`(name / bio)と `posts`(title / summary(maxLength 200, required) / body(RICH_TEXT) / tags(SELECT many, FLIX/GRAPHQL/CMS/POSTGRES) / publishedOn(DATE) / featured(BOOLEAN) / author(REFERENCE→authors) / slug(SLUG, required, unique, sourceField=title))を確認。どちらの型も `previewUrl` は null。

## シチュエーションごとの結果

### 1. 公開してすぐ取り消し — できた(迷った点あり)
create → publish_check → publish → impact(UNPUBLISH) → unpublish → publish が一通り通った。
迷った点: `slug` は `sourceField: title` なのに create 時に自動生成されず、publish_check で「fields.slug に値が要ります」と初めて分かった。create の応答は成功(version 1)なので、必須欠落に気付くのが遅れる。

### 2. 参照のある記事 — できた
未公開著者を参照した記事は `publish_check` が `ok: true`・`violations: []`・`unpublishedDependencies: [著者]` を返す。しかし素の `publish` は INVALID(参照先が未公開)で失敗し、`withDependencies: true` で著者ごと公開できた。
その後の著者 unpublish は `impact` の `breaks` に記事が出て、`unpublish` 自体も「公開中の entry が参照しています」で拒否された。挙動は正しいが、publish_check の `ok: true` と publish の失敗が矛盾している(後述)。

### 3. 10 件作って探す — 一部できなかった
10 件作成し 5 件公開。
- FLIX タグの物: タグでの絞り込み API は無い。`search: "FLIX"` の全文検索でタグ値にもヒットする(本文にタグ名を含まない S3-11 が `search: "CMS"` で出た)ので代用はできるが、本文に "FLIX" と書いてあるだけの記事も混ざる。
- 公開中の物: `stage: PUBLISHED` で 7 件取れた。ただし `totalCount` は 12(全件)で、絞り込み後の件数ではない。
- 2 ページ目: `first: 5, skip: 5` は取れる。しかし `stage: PUBLISHED` と組み合わせると、description の通り「このページの中から」絞るため 2 ページ目は 0 件になった。公開中の物だけを正しくページングする方法が無い。
- 公開日・featured での絞り込み・並び替えも無い(更新順固定)。

### 4. 直して戻す — 半分できた
公開済み記事の本文を update → stage が CHANGED になり、`diff_entry(PUBLISHED→DRAFT)` で行差分(SAME/DEL/ADD)が見えた → 再公開できた。
「前に公開した中身に戻す」は revert API が無い。`get_entry(stage: PUBLISHED)` で公開中の本文を読み、その Markdown を `update_entry` で書き戻して手動復元した。復元後 diff は空 `[]` になったが、stage は CHANGED のまま(内容が同じでも下書き扱い)。
`diff_entry` の `versionId` は「get_entry の versions」から取ると書いてあるが、get_entry の応答に `versions` は無く、`versionId: "4"` を試しても NOT_FOUND。過去バージョンを指定する手段が見つからなかった。

### 5. 競合 — できた
2 回 get_entry(共に version 5)→ version 5 で保存(→6)→ もう一度 version 5 で保存 → `CONFLICT`(expectedVersion 5 / actualVersion 6、「読み直してから保存してください」)。
復旧: get_entry で読み直し、相手の変更(summary)と自分の変更(title)が別フィールドである事を確認し、version 6 で自分の変更を再適用(→7)。エラーは分かりやすい。ただし「相手が何を変えたか」を見るには自分の手元の古い値と比べるしかない(versionId 指定の diff が使えないため)。

### 6. 読み取り専用の鍵 — できた(期待どおり拒否)
`cms-reader` で create_entry は `FORBIDDEN (writeEntries)`、publish は `FORBIDDEN (publishEntries)`。下書きの get_entry / search_entries(stage: DRAFT)は読めた。preview_url もトークンを発行できた(reader でも発行できてよいかは要検討)。
迷った点: reader 側にも create/update/publish/unpublish のツールが並んでいるので、ツール一覧だけでは権限が分からない。

### 7. 消したい — できなかった
`impact(action: DELETE)` はあるのに delete ツールが無い。間違えて作った記事(S3-11 など)は残ったまま。「削除できない事」を知らせる手段も無く、下書きが増えていく。

### 8. 画像と動画 — ほぼできなかった
- `![alt](asset:ID "caption")` / `@[video](asset:ID)` / gallery の構文は受理されるが、asset を探す・アップロードするツールが無いので ID を得られない。存在しない ID で create は通り、publish_check で「asset がありません」と出る。
- 外部 URL の画像 `![alt](https://…)` は画像にならず、エスケープされた文字列 `!\[外部画像\](https://…)` として本文に残る(HTML でも `<p>![外部画像](…)</p>`)。
- YouTube URL の行は embed になった。
- gallery を Markdown で読み戻すと alt が消え、alt が caption 位置に移動していた(`![a](asset:x1)` → `![](asset:x1 "a")`)。

### 9. 下書きを人に見せる — できなかった
`preview_url` は `token` と `expiresAt` を返すが、型に previewUrl が無いので `url: null`。トークンをどこに付けて何を開けばよいか分からず、人に渡せる URL にならなかった。

### 10. 予約公開 — できなかった
予約公開の API が無い。`publishedOn` に `2026-09-14T09:00:00+09:00` を入れる事はできた(DATE 型でも時刻付き ISO を受理し、そのまま返る)が、これは表示用の日付であって公開のトリガーにはならない。実際に公開するには当日に publish を呼ぶ必要がある。

### 11. 巨大な本文 — できた
約 60 KB(同じ段落 ×100)の本文を create し、`get_entry(format: text)` で全文が欠けずに戻った。search_entries でも本文全文が平文で返るため、1 件でも応答が非常に大きい(一覧用途では要約したい)。

### 12. 値の形 — できた(エラーは分かりやすい)
正しい形: `tags: ["FLIX"]`、`publishedOn: "2026-09-01"`、`featured: true`、`author: "<entry id>"` で通る。
間違った形のエラー:
- `tags: "FLIX"` → 「fields.tags: 配列にしてください」
- `publishedOn: "来週"` → 「ISO 8601 の日時(2026-09-08T09:00:00Z)か日付(2026-09-08)にしてください」
- `featured: "yes"` → 「真偽値にしてください」、`tags: ["RUST"]` → 「選択肢(FLIX, GRAPHQL, CMS, POSTGRES)にありません」(複数同時に返る)
- `author: {"id": ...}` → 「entry の id にしてください」
- `author: "nonexistent-id"` → create は**通る**。publish_check で「参照先はありません(消されています)」と出る。

### 13. 要約の上限 — できた(publish までは行けない)
summary 250 文字は create でも update でも「200 文字以内にしてください」で保存自体が拒否される。したがって「公開しようとする」段階には到達しない。エラーは明確。

## 足りない API(無くて困った物)— 優先度順
1. **delete_entry** — impact(DELETE) だけあって消せない。誤作成の後始末ができない。
2. **フィールド条件での検索・並び替え**(tags / featured / publishedOn 範囲、公開日順)— 全文検索と更新順しか無く、ブログの一覧を組めない。
3. **stage 絞り込みをサーバ側で行うページング** — 現状は取得後にページ内で絞るので「公開中の 2 ページ目」が取れず、totalCount も絞り込み前の値。
4. **バージョン一覧と revert** — get_entry に versions が無く、diff の versionId が使えない。「前の公開内容に戻す」を安全にやる手段が無い。
5. **asset の一覧・アップロード(または外部 URL 画像の許可)** — 画像・動画を本文に入れる入口が無い。
6. **予約公開(publishAt)** — 日時指定の publish が無い。
7. **preview_url の URL 組み立て方**(型に previewUrl を設定する API か、トークンの使い方の明示)。
8. **権限の問い合わせ**(whoami / 使える操作の一覧)— reader 鍵でも書き込みツールが見えるため、試して FORBIDDEN を受けるしかない。

## description や応答の分かりづらさ — 優先度順
1. **publish_check の `ok: true` なのに publish が失敗する** — description は「violations が空なら publish は通る」だが、unpublishedDependencies があると素の publish は INVALID。`ok` の意味を「withDependencies なしで通るか」にするか、description に注記が要る。
2. **slug の自動生成** — `sourceField: title` から自動で埋まると読めるが、実際は create 時に自分で入れないと公開できない。create の応答か list_types の説明で分かるようにしてほしい。
3. **diff_entry / get_entry の versionId** — 「get_entry の versions」は存在しない。未公開時の diff は行差分ではなく doc(JSON)の ADDED になる点も description(「Markdown の行差分」)と違う。
4. **search_entries の stage** — 「このページの中から絞る」と書いてあるが、ページングと組み合わせると実用にならない事、totalCount が絞り込み前である事が読み取りにくい。
5. **get_entry(stage: PUBLISHED) の応答の stage / version** — 公開中の中身を返しているのに `stage: CHANGED`、`version` は下書きの値。どちらの中身を見ているのか応答だけでは分からない。
6. **preview_url の token の使い方** — url が null のとき、token をどう使うかの案内が無い。
7. **外部 URL 画像が使えない事**が description に書かれていない(「画像は asset:ID」とだけある)。
8. **search_entries の本文全文返却** — 「平文にして返す」とあるが、60 KB の本文もそのまま返る。一覧用途では切り詰めるか、返すフィールドを選べるとよい。

## バグと思う物 — 優先度順
1. **外部 URL 画像がエスケープされた文字列として保存される** — 画像として扱わないなら受理時に INVALID にするか、少なくとも文字列に化けさせない方がよい。
2. **gallery の Markdown 往復で alt が消え、alt が caption の位置に入る**(`![a](asset:x1) ![b](asset:x2)` → `![](asset:x1 "a") ![](asset:x2 "b")`)。
3. **存在しない entry id を author に入れても create/update が通る** — 参照先の存在確認が publish_check まで遅延する。型違い(オブジェクト)は即時に弾くのに、存在しない id は弾かないのは不揃い。
4. **公開中と同じ内容に戻しても stage が CHANGED のまま** — diff が空なのに「変更あり」と表示される。内容比較で PUBLISHED に戻すか、仕様なら明記が要る。
5. **DATE 型が時刻・タイムゾーン付きの値を受理し、そのまま返す** — 日付だけの値は `T00:00:00Z` に正規化されるのに、時刻付きは正規化されない。型が DATE なら日付に丸めるか拒否する方が一貫する。
6. **cms-reader でも preview_url が発行できる** — 読み取り専用の鍵に下書き公開前プレビューのトークン発行を許すかは権限設計として要確認。
