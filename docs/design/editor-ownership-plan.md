# エディタの DOM を誰が持つか（2026-09-12。レビュー後に全面改訂）

初版は「持ち主を Decoration / Elm / node view の 3 つに決めて順に寄せる」という
計画だった。批判者 2 人に叩かせた結果、**中心の見立てが誤りだったので書き直した。**

## 初版の何が誤りだったか

| 初版の主張 | 実際 |
|---|---|
| 許可リスト 43 件 | **45 件**（block-edges 1 と tiptap-editor の bar 1 を数え落とし） |
| TS 6536 行 | **7151 行** |
| Decoration で測定が消えるのは 25 件 | **4〜6 件**。1 件ずつ当たって数え直した |
| 第 1 段の後に許可リスト 18 件 | **39 件**が現実的な着地 |
| 「リンクの面を Elm に移して 316 行消えた」 | TS は 310 行減ったが Elm に 599 + 217 + テスト 67 行増えた。**全体は倍以上** |
| A を先にやれば B に渡す物が中身だけになる | 成り立たない。Elm の面は ProseMirror の外に描かれるので、今も矩形を渡している |
| コードの強調行の帯を Decoration へ | **すでに `calc()` で測っていない**。移す動機が無い |
| `math.ts` は計画の対象外 | **すでに Decoration で書かれている**。手本がここにあった |

## 分け直し: 道具ではなく「何に貼り付いているか」で切る

技術（Decoration / Elm / node view）で切ると、1 つの段の中に「測定が消える物」と
「消えない物」が混ざる。**貼り付いている先で切る。**

| 種類 | 件数 | 何をするか |
|---|---|---|
| CSS だけで測定が消える | 3 | `transform` などに置き換える |
| doc の位置に貼り付く | 4 | `Decoration.widget`（「+」だけ） |
| **画面の矩形に貼り付く** | **33** | **測り方を 1 か所に寄せる**（Decoration にも Elm にもならない） |
| 打てなくする | 4 | そのまま。手組みで良い |

**一番大きいのは 3 番目で、初版はここを「移さない」と書いて対象外にしていた。**
表の掴み（14 件）・表の帯・落とし先の影・選択に浮く帯・乗せた時の吹き出しが入る。

## やる事

### 0. 見張りの穴を塞ぐ（計画と無関係。今すぐ）

`scripts/editor-check.mjs` は `getBoundingClientRect` と `style.top/left` しか見ない。
**すり抜けている測定が 7 か所ある。**

```
web/block-edges.ts:115    getBoundingClientRect?.()   ← ?. が挟まって当たらない
web/quote-node.ts:270,272 cite.offsetHeight → style.height
web/math.ts:221,227       offsetHeight → style.height
web/tiptap-editor.ts:416  bubble.offsetHeight
web/tiptap-editor.ts:747  captionUrl.offsetWidth
```

規則に `offsetHeight` / `offsetWidth` / `style.height` / `style.setProperty` / `cssText` を
足し、`?.` も当たるようにする。**これを塞がないと「許可リストを下げる」を守っても
手組みは静かに戻る。**

### 1. 未解決の不具合を潰し、通しレビューを受ける

批判者 2 人が同じ結論だった。書き換えの前に、引き継ぎの 10 件と今日の分を片付け、
ユーザーの言う通しレビューを先に通す。**書き換え途中のコードをレビューに掛けない。**

### 2. CSS で消える 3 件

キャプションの URL の中央寄せを `transform: translateX(-50%)` に。危険 0、即日。

### 3. 「+」だけを Decoration.widget に。**そこで止めて測る**

一番小さく、一番よく壊れた 4 件。`ResizeObserver` と `requestAnimationFrame` ごと消える。
ただし「移すだけ」では終わらない。引っ掛かるのが 3 つある。

- **`editor.isFocused` が decoration から見えない**（focus / blur は transaction を作らない）
- **面が開いている間の条件が壊れる。** 一覧は `.ProseMirror` の外にあるので、
  `:focus-within` で代用すると面に焦点が移った瞬間に「+」が消える
- **widget の DOM を使い回さないと**、面が古い要素を基準に置かれる（`text-marks.ts` の `held` と同じ工夫）

**先に検査を書く**（「面を開いたまま + が残る」）。移した後に、減った行数と所要時間を
記録する。**この数字を見てから 4 に進むかを決める。**

### 4. 画面の矩形に貼り付く 33 件 — 測り方を 1 か所に寄せる

`place.ts` に「基準の要素 + クリップ枠 → 置き直し（scroll / resize / ResizeObserver 込み）」を
1 つ作り、19 か所を載せ替える。見張りの規則も「素で測る」と「部品経由で測る」を
区別できるようにする。

**測定は消えない。1 か所になるだけ。**それでも、今の「浮く面が取り残される」系の
不具合が 1 か所の直しで全部に効くようになる。

### 5. node view の中身を Elm へ — 保留

`image-node.ts` 888 行のうち Elm が引き取れるのは帯の約 310 行。リンクの面の実績
（TS −310 / Elm +883）を踏まえると、**総量は増える**。3 の実測を見てから判断する。

## React / Preact を入れない

UI のフレームワークが 2 つになる。Elm で書ける物を React で書く理由が無い。

## 見込み（初版から下方修正）

| | 許可リスト | TS の行 |
|---|---|---|
| 今 | 45 | 7151 |
| 0 の後 | 52（穴を塞ぐので**増える**） | 7151 |
| 2・3 の後 | 45 前後 | −200 〜 ±0 |
| 4 の後 | 45 前後（規則が変わるので数の意味が変わる） | −300 前後 |

**行数は減らない。** 初版の「6536 → 5000」は根拠が無かった。減るのは行数ではなく
「同じ不具合が別の場所で再発する回数」で、そこを測る物差しを持っていない事自体が
今の弱点。0 と 3 で作る。

## 進め方の守り

- **1 つ移すごとに検査を先に書く。** ただし今の 117 件はクラス名と DOM の構造に
  張り付いていて、Decoration にすると検査も書き換わる。**構造に依存しない物差し**
  （アンカーとの座標の一致、高さが transaction 無しで変わった時の追随）を先に足す
- **区切りよく終われる単位でコミットする。** 途中で止まると同じファイルに 2 通りの
  流儀が混ざり、今より悪くなる
- **段ごとに実測を記録する。** 見積もりが 2 回続けて外れている

## 決め（2026-09-12）: 独立した整理はやらない

**行数を減らす整理は取り下げる。** `tiptap-editor.ts` の 1687 行、`image-node.ts` の
889 行はそのままにする。TipTap の拡張は 1 つ 1 つが独立した設定の塊で、ファイルを
割っても読む量が変わらない。部品化のコミット `4a9e071` は `+2206 / −620` の純増だった。

**やるのは「画面の矩形に貼り付いている 33 件」だけ。** これは行数ではなく不具合の
種類が 1 つ消える話で、実績がある:

- 本文をスクロールすると面が取り残される（直した）
- ウィンドウを変えると追従しない（`watchWindowResize` で直した）
- 枠からはみ出して上の帯に重なる（2026-09-12 に直した。`ui.ts` の `stickyFloor` で貼り付いた帯の下端を実測し、Floating UI の `shift` の `padding` に getter で渡す）

全部「自分で測って自分で置く」から起きている。`ui.ts` の `popover()` に寄せると
置き場所の決定が 1 箇所になり、`bounds`（枠に収める）を 1 回書けば 33 箇所に効く。

### 順

1. バブルメニューが枠からはみ出す件を、**その 1 件の対処にせず `popover()` の
   `bounds` として書く**。検査は先に `dev/checks/invariants.test.ts` へ（矩形が
   本文の枠に収まっているか。上端と下端の 2 件）
2. 以後、33 件を**不具合を直すついでに 1 件ずつ**寄せる

**独立した「リファクタリング作業」として切り出さない。** 1 件ずつ寄せる方が効果を
確かめられる。進み具合は `scripts/editor-check-allow.json` の合計（今 67 件 / 15
ファイル）で数字として見える。
