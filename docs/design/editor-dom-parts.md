# エディタの DOM の部品（2026-09-11）

同じ形のバグが繰り返し出たので、部品にまとめて「そもそも起きない」形にする。

## 今日出た不具合の傾向

エディタの中の DOM 操作で 15 件ほど、Elm 側は 0 件。**型では防げない種類**ばかりで、
ProseMirror が DOM を所有しているという前提と、手で書いた DOM の間の隙間に落ちている。

| 形 | 出た場所 |
|---|---|
| 帯に文字が打ててしまう（doc に入らず見た目にだけ残る） | gallery の帯、コードブロックの帯。他の帯も未確認 |
| 浮く面がスクロールや高さの変化で取り残される | 「+」、言語の候補。他の面も未確認 |
| placeholder が消えない | 引用の出典 |
| 入れた直後に焦点が中に入らない | 数式、URL を貼った時 |
| 矢印キーが食われて外に出られない | 数式、引用の出典、コードのファイル名 |
| 入力欄に余計な下線が出る | 画像の ALT、引用の出典 |
| ボタンが 1 回目の押下で効かない | 引用の「出典を追加」 |

## 作る部品（`admin-ui/web/ui.ts`）

### `bar(...)` — ブロックの帯
- 作った時点で `contentEditable = "false"` と `user-select: none` が入る
- 中に入れたボタンと入力は普通に操作できる
- 画像・gallery・コード・数式・リンクカード・表が同じ物を使う

### `field({ placeholder, value, onCommit, onLeave })` — ブロックの中の入力
- placeholder は素の `<input placeholder>`（自前の要素で出さない）
- 上下の矢印は「端の行でだけ外へ出る」を内蔵（`leaveBlock` を呼ぶ）
- Enter で確定、Esc で取り消し、blur で書く / 書かないを選べる
- focus の見た目は文字の色だけ（下線や破線を出さない）
- `stopEvent` に渡す判定も部品が持つ

### `popover({ anchor, place })` — 浮く面
- **親を基準に置く**（`position: absolute` + 親に `relative`）。画面座標を計算しない
- 画面の端で収まらない時だけ、反対側に返す
- 外を押すか Esc で閉じる
- 言語の候補、ALT の入力、リンクの URL、配置の 3 択が同じ物を使う

### `iconButton({ icon, title, onClick })`
- `title` と `aria-label` が必ず入る（文言の見張りに乗る）
- `aria-pressed` の出し分けも部品が持つ

## やらないこと

- 選択に追従する面（BubbleMenu、キャプションの帯）を Elm に移すのは別の話（`admin-ui-shared-ui.md` の境界の節）
- ProseMirror の plugin（入力規則、疑似行、貼り付け）は対象外

## 進め方

1. `web/ui.ts` を作り、まず**帯と浮く面**を移す（今日のバグの 2 大要因）
2. 既存の帯を 1 つずつ差し替え、差し替えるたびに「文字が打てない」「スクロールでずれない」を確かめる
3. 入力とアイコンのボタンを移す
4. `scripts/rich-check.mjs` に「すべての帯で文字が打てない」「すべての浮く面がスクロールでずれない」を横断の確認として足す

## 効果の見込み

今日の 15 件のうち、帯（2 件以上）・浮く面（2 件以上）・placeholder・下線・矢印キー（3 件）は
部品があれば起きなかった。**10 件前後がゼロになる**計算。

## 追記: マークの抜け方（2026-09-12）

ユーザーの報告 2 件。どちらも「掛けた装飾から抜けられない」という同じ形の困りごと。

### 1. 段落を変えても装飾が続く

下線を掛けた段落で Enter を押すと、次の段落も下線のまま。Notion も note も**段落を変えたら装飾を落とす**。

**決め**: Enter で新しい段落を作った時は掛かっているマークを落とす。
ただし**リストの項目を増やす時は残す**（箇条書きの中で太字を続けたい場面がある）。

### 2. インラインコードの箱から抜けられない

箱の右端で打った文字は箱の中に入り続ける（ProseMirror の既定）。
バッククォートだけは 2026-09-11 に外へ出るようにしたが、普通の文字は入ったまま。

**決め**（3 つとも入れる）:
- **箱の右端で → キー**を押すと箱の外に出る（ProseMirror の作法）
- **ツールバーのボタンをもう一度押す**と外れる。カーソルが箱の中にある時に効くか確かめる
- **Notion の「Space 2 回で抜ける」も採る。** 打っている流れの中で、カーソルを動かさずに
  抜けられる方が強い。1 つ目の Space は箱の中に残し（`a b` のようにコードの中の空白を書ける）、
  2 つ目の Space が箱の外に入る

同じ問題は他のマーク（下線・蛍光ペン・上付き・下付き）でも起きるので、**コードだけでなく全部**に効かせる。

抜ける道は 3 つ（→ キー / Space 2 回 / ボタンをもう一度）。本文は `admin-ui/web/mark-escape.ts`。

**TipTap の `exitable` は当てにならない。** 持っているのは `code` だけで、`math`・下線・蛍光ペン・
上付き・下付きには無い。しかも `Mark.handleExit` は `$from.pos === $from.end()` でしか動かず、
**文字を選んでツールバーで掛けた直後には効かない**（帯の道具は選ばないと押せないので、掛けた
直後は必ずこの形）。抜けた印に空白も 1 つ打つ。`mark-escape.ts` を `priority: 150` で先に置く。

## 追記: 確認の仕方（2026-09-12）

「直したつもりが直っていない」が繰り返し起きた。原因は**実機で確かめていない**こと。
あるエージェントは自前の簡易ページ（`probe.html`）で確かめ「効いています」と報告したが、
実機ではインラインコードも数式も右キーで抜けられなかった。

### 守ること

1. **必ず dev サーバの実物**（`localhost:5173` の実際の編集画面）で確かめる。
   一時的な HTML も簡易ページも使わない。拡張の組み合わせと入力規則が本番と変わる
2. **`setContent` で状態を作らない。実際に打鍵する**（`page.keyboard.type` と `press`）。
   人と同じ手順を通さないと、入力規則と node view の組み合わせが本番と違う形で動く
3. **打った直後の画面を撮り、報告にパスを書く。**「実測しました」だけの報告は受け付けない
4. **直す前にまず再現する。** 再現できない物は「再現しませんでした」と報告し、直さない

### 今日この形で外した見立て

| 症状 | 私の見立て | 実際 |
|---|---|---|
| バッククォート 1 つでコードになる | 入力規則が壊れている | 箱の右端で打った時だけ。ProseMirror の既定 |
| 「+」が gallery でずれる | gallery の計算が特別 | 高さが transaction 無しで変わる時すべて |
| 引用と数式が重なる | 引用の CSS | 重なっていない。乗せると下が動くだけ |
| コードは右キーで抜けられる | 簡易ページで確認 | 実機では抜けられない |

## 追記: 検査の環境（2026-09-12 の決め）

### 当面の運用

Playwright での確認を**止める**。時間とトークンがかかりすぎる
（エージェント 1 人あたり 10 万〜25 万トークン、5〜30 分。大半が「サーバを立てる → 画面を開く →
打鍵する → 撮る」に消えた）。

エージェントは**実装と `npm run check` までで止め、確かめていない事を正直に書く**。
実機の確認は人が行う。

### 決めたい事（調査中）

**検査を層に分ける**のが本命。

- **速い層**（ミリ秒）: ProseMirror の状態だけを扱う。doc を組み立て、キーを送り、結果の doc と
  選択を読む。画面を描かない。今日直した「右キーで抜ける」「Space 2 回」「Enter で装飾が落ちる」
  「入力規則」は全部ここで確かめられるはず
- **遅い層**（秒）: 見た目。帯の位置、はみ出し、重なり、スクロールでのずれ

今の `rich-check.mjs` は 190 件すべてが遅い層。大半は速い層に移せるはず。

道具の候補: **Vitest のブラウザモード**（Vite の設定をそのまま使うので「簡易ページでは動くが
実機では動かない」食い違いが起きにくく、**TipTap の内部状態を直接読める**）、Cypress、WebdriverIO。

### 決まったら整備する物

- 速い層と遅い層を分けた検査の土台
- サーバ無しで動く開発用の画面（名前を付けた初期状態を切り替えられる）
- 検査を回すのは CI（エージェントは書くだけ）
- 操作を記録して検査に起こす仕組み

**システムに関わる部分（CMS の Flix、DB、認証）は別。**ここはエディタの検査とは分けて考える。

## 追記: 見張りで禁じる物（2026-09-12）

部品を作っても、部品を使わずに手組みすれば同じ不具合が戻る。`admin-ui/scripts/editor-check.mjs`
が `web/*.ts` のコード（コメントは見ない）を読んで、手組みの印を落とす。`npm run check` の一部。

禁じるのは 4 つ。どれも「その形を書いた＝部品を使っていない」の印で、部品そのものを書く
`web/ui.ts` と `web/place.ts` だけは対象外。

| 規則 | 落とす形 | 使う部品 |
|---|---|---|
| `editable` | `.contentEditable =` | `bar(...)` / `popover(...)`（打てない事と押し始めの止めが入っている） |
| `bar` | `.className = "…-bar"` | `bar({ className })` |
| `measure` | `.getBoundingClientRect()` | `popover(...)`（親を基準に置く）/ `placeUnder(...)` |
| `place` | `.style.position / top / left / right / bottom =` | 同上 |

### 許可リスト

今ある分は `admin-ui/scripts/editor-check-allow.json` が**ファイルと規則ごとの件数**で押さえて
あり、増えた時だけ落ちる。減らしたら count も下げる（下げ忘れると、新しい手組みがその枠に隠れる
ので、見張りが「減っています」と言う）。

行番号では持たない。1 行足しただけで全部ずれるため。同じファイルの同じ規則で 1 件直して 1 件
足すと素通りするが、そこはレビューで見る。

外す時は count を減らし、`why` にどう部品へ寄せたかを残す。
