### Markdown の方言に足した物

| 物 | 書き方 | 理由 |
|---|---|---|
| セルの結合 | セルの中身の後ろに `{colspan=2 rowspan=3}` | GFM に結合の書き方が無い。既にある `{#id}` / `{width=W height=H}` と同じ `{key=value}` に揃えた |

- `colspan=1` は書かない（HTML の `spanAttrs` と同じ「2 以上の時だけ」）
- 覆われるセルは空のセルとして Markdown に置く（省くと区切り行と寄せの列がずれ、GFM の読み手に表として見えない）
- 結合を 1 つも持たない `{…}` は後ろ書きとして食べない（`{x=1}` で終わる普通の文が読み戻しで消えるため）
- 上限 `maxCellSpan() = 1000` を `validate` にも置いた（上限が無いと大きな値 1 つで Markdown と HTML がいくらでも膨らむ）

### 入れ子の線引き

**折りたたみの中に折りたたみは入れない。** Markdown の `</details>` は最初の 1 つで閉じるので、内側の閉じタグで外側が閉じて往復で形が変わる。
引用の入れ子を断っているのと同じ理由。段落・コードブロック・表は入る。

### サンプルブログは専用のスキーマにする

`import/microcms/schema/` は実在の会社のスキーマ（9 型・relation・relationList・repeater・unsupported）で、取り込みの実力を測る材料として残す。
作例（`~/Desktop/flix-cms-example`）が前提にしている blogs / authors / tags は **`import/blog-example/` に別に置き、`make import-blog-example` で `blog-example` プロジェクトに流す**。
apiId が衝突するので同じプロジェクトには流さない。作例は URL を `/p/${CMS_PROJECT}/graphql` と組み立てているので、噛み合わせに要るのは環境変数 1 本。
