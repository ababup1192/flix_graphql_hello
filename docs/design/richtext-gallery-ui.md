# 画像とギャラリーの作り直し（2026-09-11）

ユーザーの不満（自動でギャラリーになる説明が無い、解除できない、列数の帯が分かりにくい、
キャプションの位置が微妙）と、他社の調査を受けた決め。

## 他社（調査で裏が取れた分）

| | 作り方 | 解除 | 列数 | キャプション | 出力 |
|---|---|---|---|---|---|
| note | **横並び自体が無い** | — | — | 画像の下。ツールバーには無い | `figure > img + figcaption` |
| Ghost | gallery card を選ぶ | 作り直し | 自動（行に 3 枚まで） | **カード全体に 1 つ** | `figure` の中に行の `div` |
| WordPress | 画像を選んで「ギャラリーに変換」 | **「画像に変換」がある** | 人が選ぶ | **全体 + 画像ごとの 2 層** | `figure` に flex と列数 |
| Medium | 画像を横に並べる操作 | ドラッグで戻す | **枚数から自動** | 行ごと | 包む要素が無く、各 figure が「行の開始／継続」を持つ |
| Substack | ツールバーから gallery | 見つからず | **選べない** | 画像ごと（Web はホバー、メールでは落ちる） | クライアントで組み立て |

分かったこと。**列数を人に選ばせているのは WordPress だけ。解除を持つのも WordPress だけ。**
note の画像のツールバーは リンク / ALT / 縮小拡大 / 削除 の 4 つで、キャプションは含まない。

## 決め

### 1. node は分けず、`image` に複数の画像を持たせる

今は `image`（1 枚）と `gallery`（複数枚）の別 node で、相互の変換が作り直しになる。
**`image` が 1 枚でも複数枚でも持てる形**にすれば、変換が「子を足す / 減らす」だけで済む。
1 枚に戻った時に自動で単独の見た目になるのも自然に効く。

### 2. 列数は人に選ばせない

**枚数から決める**（2 枚なら 2 列、3 枚なら 3 列、4 枚以上は 3 列で折り返すか横スクロール）。
分かりにくい帯が消える。`attrs.columns` は読む側だけ互換で残す。

### 3. 解除は帯から

画像を選んだ時の帯に「並べる / 1 枚ずつ」の切り替えを置く。WordPress と同じで、他社が揃って落としている穴。

### 4. キャプションは画像ごとだけ（1 層）

**ぜんたいのキャプションは持たない**（2026-09-11 にユーザーが判断）。
写真ごとの説明で足りる場面がほとんどで、作りが単純になり HTML の入れ子も浅くなる。
WordPress は 2 層だが、Ghost は全体に 1 つ、Substack と Medium は画像ごと。揃っていない。

### 5. 横スクロールは採らない（保留）

4 枚以上で縦に伸びるのを避けたい、という要望は分かる。ただし読み手が続きに気づかない、
という批判が定番で、公開側の CSS で決められる話でもある。
**HTML は並べ方を持たず、サイト側の CSS が折り返すか横に送るかを決める。**
編集画面では折り返して出す。

## HTML の形

ユーザーの提案どおり、**外側を `figure` にする**（Ghost と WordPress が同じ形）。

```html
<!-- 1 枚 -->
<figure>
  <img src="a.jpg" alt="">
  <figcaption>説明</figcaption>
</figure>

<!-- 複数枚。画像ごとのキャプションは img を figure で包む -->
<figure data-gallery="3">
  <img src="a.jpg" alt="">
  <figure><img src="b.jpg" alt=""><figcaption>2 枚目だけ説明</figcaption></figure>
  <img src="c.jpg" alt="">
  <figcaption>3 枚の写真</figcaption>
</figure>
```

画像ごとのキャプションが無ければ素の `img` を並べる。ある画像だけ `figure` で包む。
`data-gallery` の値は枚数（列数ではない）。並べ方はサイト側の CSS が決める。

## Markdown

今の形（1 行に画像を並べ、次の行に枚数分のキャプションを `*…*` で空白区切り）を維持する。
全体のキャプションの置き場だけ決めが要る（案: 画像の行の前の行に `**…**`、あるいは
画像ごとのキャプションの行の後ろにもう 1 行）。実装時に決める。

## やる順

1. CMS: `image` を複数枚持てる形に。`gallery` は読む側だけ互換。HTML と Markdown の往復
2. 画面: node を 1 つにし、帯に「並べる / 1 枚ずつ」を足す。列数の帯を消す
3. 作例の CSS: `figure[data-gallery]` の並べ方（折り返し）

1 は今日やった「キャプションを内容にする」と同じ規模。2 は node view の作り直し。

## 画面の実装（2026-09-12）

`web/image-node.ts` を 2 つの node に分けた。

- `image`: 入れ物。`content: "imageItem+"`、`group: block`、attrs は無し。
  node view は入れ物の div で、2 枚以上の時だけ `tt-gallery` / `tt-gallery-grid` の class を付けて
  枚数から列を決める。1 枚の時は素の div で、今までの単独の画像と同じ見た目になる
- `imageItem`: 画像 1 枚。attrs（assetId / alt / href / size / align / source / sourceUrl / width / height）と、
  content にその 1 枚のキャプション。帯も枠もこちらが持つ
- 「横に並べる」は隣り合う `image` の `imageItem` を 1 つの `image` に移すだけ、
  「1 枚ずつに戻す」は `imageItem` の数だけ `image` に分けるだけ。**node は作り直さない**
- 読む時だけ `liftImageItems` が旧 `gallery` と旧 `image`（attrs.assetId）を写す。書くのは新しい形だけ

`image` は `isolating`。素の block だと、画像の下の段落に次の画像を入れた時に
ProseMirror が入れ場所を探して前の `image` まで範囲に入れ、1 枚目が置き換わる。
`defining` は使わない（型だけ残して中身を既定の `imageItem` で埋め直し、assetId が消える）。
